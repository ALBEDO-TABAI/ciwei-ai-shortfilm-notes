# 01 方法论与技术要点（已按提示词对比修正）

## 口播流程

1. 人物资产 → GPT 推一镜到底剧情 → 人选方向  
2. **单独问**：30 秒内拍不拍得完  
3. 剧本 → 半俯视 3D 调度图（颜色区分人物 + 移动线 + 起停机位）  
4. 调度图 + 剧本 → Codex / Blender 粗模 Previs  
5. 人物资产 + 运镜视频 → Seedance 2.5 出成片段落  

工具链：Seedream 5.0 / Midjourney 定妆 → Nano Banana 四视图 → GPT-5.6 做剧本与时间审查 → Codex+Blender 做运动 → Seedance 2.5 出画面。

## 看完提示词后补上的要点

1. **复杂运镜的真正控制对象是“运动”，不是“更会写镜头词”。**  
   好提示词几乎不写 “cinematic camera moves gracefully”，而是要求输出可播放的 Previs。口播里的“以后别再写运镜脚本”应理解为：别只写脚本，要把脚本变成几何运动。

2. **先锁信息链，再锁镜头。**  
   GPT 复核截图证明：失败点是观众看不清“真信→掉落→假信→递交→记者拍到”。运镜服务于这条因果，而不是反过来。

3. **空间要写成米和秒，不要写成“宽敞大厅”。**  
   书房门到碰撞点约 3 米、碰撞点到公爵约 2 米——这种数字才能限制模型乱走位。

4. **关键动作必须可视化差异。**  
   调包这类“两个相似物交换”要主动设计：颜色标记、手套、低机位手部近景。否则再准的运镜也是无效抽卡。

5. **参考物要分层，不要一股脑塞。**  
   - 定妆图：锁脸和衣服  
   - 俯视图：锁房间坐标  
   - 粗模视频：只锁相机和走位  
   - Seedance 正文：明确“学什么 / 不学什么”

6. **导演台不是错，是成本错。**  
   方法成立的前提是：用 Codex 把高成本的三维调度自动化，而不是用更长的自然语言去模拟三维。
